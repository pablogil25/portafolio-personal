# Storytelling

Este documento define la narrativa profesional del portafolio de Pablo Rodriguez Gil. La meta es que el sitio no se sienta como una lista de secciones, sino como una historia de confianza: de claridad inicial a evidencia tecnica y contacto.

## Idea Narrativa Principal

Pablo Rodriguez Gil es un Software Developer que convierte problemas reales en software funcional: backend, APIs, automatizaciones y aplicaciones web construidas con tecnologias modernas.

La historia no debe decir "mira mi portafolio". Debe decir:

"Estos son los problemas que puedo resolver, esta es la evidencia de que ya lo estoy haciendo y este es el siguiente paso para conversar."

## Promesa Profesional

La promesa del sitio:

Pablo puede integrarse a un equipo para construir soluciones web, backend, APIs y automatizaciones con criterio tecnico, aprendizaje constante y experiencia practica en proyectos reales.

Decision:
Esta promesa es fuerte porque combina capacidad tecnica, utilidad de negocio y honestidad profesional. No intenta vender seniority que no corresponde; vende potencial confiable respaldado por trabajo real.

## Arco Narrativo Del Sitio

### Acto 1: Claridad

Pregunta del visitante:
"Quien es esta persona y que hace?"

Respuesta del sitio:
"Soy Pablo Rodriguez Gil, Software Developer enfocado en backend, APIs, automatizacion con Python y aplicaciones web."

Emocion buscada:
Comprension inmediata.

Riesgo a evitar:
Abrir con frases genericas, animaciones o informacion personal que no ayude a decidir si seguir leyendo.

### Acto 2: Relevancia

Pregunta del visitante:
"Esto encaja con lo que necesito?"

Respuesta del sitio:
"Trabajo con Python, JavaScript, Node.js, React, Laravel, PHP, MySQL y Git para resolver problemas de software, automatizacion y desarrollo web."

Emocion buscada:
Interes.

Riesgo a evitar:
Mostrar tecnologias sin explicar su uso.

### Acto 3: Evidencia

Pregunta del visitante:
"Puede demostrarlo?"

Respuesta del sitio:
"Participo en proyectos reales como RapiMecanica y GoClean, y tambien desarrollo automatizaciones con Python."

Emocion buscada:
Confianza.

Riesgo a evitar:
Presentar proyectos como tarjetas visuales sin problema, rol ni resultado.

### Acto 4: Criterio

Pregunta del visitante:
"Como piensa y como trabaja?"

Respuesta del sitio:
"Analizo problemas, separo responsabilidades, construyo backend, conecto datos, documento decisiones y uso Git para mantener orden tecnico."

Emocion buscada:
Seguridad.

Riesgo a evitar:
Hablar solo de herramientas y no de criterio profesional.

### Acto 5: Decision

Pregunta del visitante:
"Que hago ahora?"

Respuesta del sitio:
"Puedes contactarme, revisar mi GitHub, conectar en LinkedIn o descargar mi CV."

Emocion buscada:
Facilidad.

Riesgo a evitar:
Terminar con una seccion de contacto fria o escondida.

## Narrativa Por Seccion

### 1. Inicio: "Esto Es Lo Que Hago"

Funcion narrativa:
Presentar al protagonista profesional.

Mensaje:
Pablo es Software Developer y construye soluciones con backend, APIs, automatizacion y aplicaciones web.

Debe transmitir:
Claridad y foco.

Justificacion:
Como Apple, la primera impresion debe ser simple y memorable. Como Vercel, debe ser directa hacia lo que se puede construir.

### 2. Prueba Rapida: "Ya Estoy Trabajando En Problemas Reales"

Funcion narrativa:
Evitar que el perfil parezca teorico.

Mensaje:
Pablo participa en RapiMecanica, GoClean y automatizaciones.

Debe transmitir:
Actividad real.

Justificacion:
Para diferenciarse de otros juniors, la historia debe mostrar practica antes de pedir confianza.

### 3. Capacidades: "Estos Son Los Problemas Que Puedo Resolver"

Funcion narrativa:
Traducir tecnologias en utilidad.

Mensaje:
Pablo puede trabajar en backend, REST APIs, automatizacion, frontend con React, Laravel, PHP, MySQL y Git.

Debe transmitir:
Competencia organizada.

Justificacion:
Stripe comunica productos complejos en bloques claros. El stack debe sentirse igual: organizado por valor, no acumulado por cantidad.

### 4. Featured Project: "Aqui Esta La Evidencia Principal"

Funcion narrativa:
Convertir la promesa en caso concreto.

Mensaje:
RapiMecanica demuestra capacidad para participar en un producto real con logica, usuarios, datos y decisiones tecnicas.

Debe transmitir:
Credibilidad.

Justificacion:
Un solo proyecto fuerte vale mas que muchos proyectos sin relato. El Featured Project debe ser el momento de mayor confianza tecnica.

### 5. Mas Proyectos: "No Es Un Caso Aislado"

Funcion narrativa:
Ampliar evidencia.

Mensaje:
GoClean y automatizaciones muestran continuidad, variedad y capacidad para resolver problemas distintos.

Debe transmitir:
Consistencia.

Justificacion:
Linear y GitHub refuerzan confianza por acumulacion de evidencia ordenada. Esta seccion debe ampliar sin dispersar.

### 6. Forma De Trabajo: "Asi Pienso Como Desarrollador"

Funcion narrativa:
Mostrar madurez.

Mensaje:
Pablo no solo usa herramientas; entiende flujo, mantenimiento, organizacion y entrega.

Debe transmitir:
Criterio profesional.

Justificacion:
En perfiles junior, el criterio puede ser mas diferenciador que agregar otra tecnologia a la lista.

### 7. Experiencia: "Donde He Aplicado Esto"

Funcion narrativa:
Ordenar trayectoria.

Mensaje:
La experiencia de Pablo se compone de proyectos reales, automatizaciones y desarrollo de software.

Debe transmitir:
Progreso honesto.

Justificacion:
La experiencia debe parecer real y verificable, no inflada. Eso genera mas confianza.

### 8. Stack: "Con Que Construyo"

Funcion narrativa:
Facilitar validacion tecnica rapida.

Mensaje:
Python, JavaScript, Node.js, React, Laravel, PHP, MySQL y Git son herramientas que Pablo usa en contextos especificos.

Debe transmitir:
Orden tecnico.

Justificacion:
Un reclutador debe poder comparar el perfil con una vacante en segundos.

### 9. GitHub: "Puedes Revisar Mi Trabajo"

Funcion narrativa:
Abrir evidencia externa.

Mensaje:
El codigo y los repositorios permiten validar como estructura y desarrolla.

Debe transmitir:
Transparencia.

Justificacion:
GitHub es especialmente importante para roles tecnicos porque permite pasar de promesa a verificacion.

### 10. LinkedIn: "Puedes Validar Y Contactar"

Funcion narrativa:
Construir puente profesional.

Mensaje:
LinkedIn permite confirmar perfil, trayectoria y disponibilidad.

Debe transmitir:
Confianza social.

Justificacion:
Un reclutador no siempre quiere leer codigo. A veces necesita un canal profesional rapido.

### 11. Certificados: "Tambien Estoy Construyendo Base"

Funcion narrativa:
Respaldar aprendizaje.

Mensaje:
Los certificados complementan la evidencia practica y muestran disciplina.

Debe transmitir:
Crecimiento.

Justificacion:
Los certificados son prueba secundaria. Deben aparecer cuando la confianza principal ya fue construida por proyectos.

### 12. Cierre: "Hablemos"

Funcion narrativa:
Transformar interes en accion.

Mensaje:
Si necesitas un desarrollador para backend, APIs, automatizaciones o aplicaciones web, Pablo esta listo para conversar.

Debe transmitir:
Disponibilidad y facilidad.

Justificacion:
El cierre debe actuar como una puerta abierta. El usuario no debe tener que decidir entre demasiadas opciones ni buscar datos de contacto.

## Historia Que Debe Sentir El Visitante

### Primeros 5 Segundos

"Entiendo quien es y que hace."

La sensacion debe ser de foco. El visitante no debe esforzarse para ubicar el rol profesional de Pablo.

### Despues De 30 Segundos

"Tiene tecnologias relevantes y proyectos reales."

La sensacion debe ser de interes. El visitante debe querer comprobar si los proyectos son tan solidos como la promesa inicial.

### Al Terminar

"Es un perfil junior con evidencia, criterio y potencial. Vale la pena contactarlo."

La sensacion debe ser de confianza suficiente para una entrevista.

## Diferenciacion Frente A Otros Juniors

El sitio debe diferenciar a Pablo por:

- Mostrar proyectos reales.
- Explicar problemas, no solo tecnologias.
- Presentar automatizacion con Python como ventaja.
- Conectar backend, APIs, frontend y bases de datos.
- Usar GitHub como evidencia.
- Presentar experiencia con honestidad.
- Tener una narrativa clara y profesional.

Decision:
Muchos portafolios junior parecen vitrinas visuales. Este debe sentirse como una presentacion profesional pensada para contratacion.

## Frases Guia Para El Copy

Estas frases no son textos finales obligatorios. Son guias narrativas para mantener coherencia.

- "Construyo soluciones web, backend, APIs y automatizaciones."
- "Trabajo con Python, JavaScript, Node.js, React, Laravel, PHP, MySQL y Git."
- "Participo en proyectos reales como RapiMecanica y GoClean."
- "Me enfoco en resolver problemas con software claro, mantenible y util."
- "Puedes revisar proyectos, codigo, LinkedIn o descargar mi CV."

## Como Debe Terminar La Pagina

La pagina debe cerrar con una sintesis de valor y una invitacion concreta.

Mensaje final recomendado:

"Estoy construyendo experiencia real en desarrollo de software, backend, APIs y automatizacion. Si buscas un desarrollador que pueda aprender rapido, aportar criterio tecnico y trabajar sobre problemas reales, hablemos."

Acciones finales:

- Enviar mensaje.
- Conectar en LinkedIn.
- Ver GitHub.
- Descargar CV.

Justificacion:
El cierre combina humildad, evidencia y disposicion. Es mas efectivo que una frase generica como "gracias por visitar mi portafolio".

## Regla Narrativa Final

Cada seccion debe responder una pregunta del visitante. Si una seccion no responde una pregunta clara o no aumenta confianza, debe eliminarse, reducirse o moverse.
